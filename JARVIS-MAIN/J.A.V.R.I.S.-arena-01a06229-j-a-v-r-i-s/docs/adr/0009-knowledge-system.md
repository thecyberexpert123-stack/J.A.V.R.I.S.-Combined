# ADR-0009: M4 knowledge system — cited facts, local verification, on-demand upstream checks

- **Status:** Accepted (2026-09-02)
- **Context:** Owner requirement #5 (deep, current knowledge) and #6 (no hallucination). The owner additionally pointed at `torvalds/linux` as a knowledge source. Constraint: the kernel tree is ~4–5 GB; vendoring it would violate minimalism (guideline 14), the artifact cap, and add unmaintainable bulk. This sandbox has no `man`/`whatis`/`sysctl` binaries and blocks `raw.githubusercontent.com`; `api.github.com` works.
- **Decision:**
  1. **Curated, cited knowledge base** (`knowledge/*.json`, versioned in-repo): every fact carries `claim`, matching `patterns`, one or more `sources` (kernel-doc path in `torvalds/linux`, man-page/spec URL, distro wiki), an optional **local verifier**, and KB schema validation at load. Facts without a passing source are refused at load — the store cannot contain uncited claims.
  2. **torvalds/linux = upstream reference, not vendored content.** Kernel facts cite `Documentation/**` paths in the upstream repo. Verification is **on-demand** (opt-in `JARVIS_ONLINE_DOCS=1`) via the GitHub Contents API against `torvalds/linux` master; the result (reachable, status, date) is cached in the state dir and shown to the user. CI runs this mode on every push, so upstream citations are re-verified continuously. No kernel content is copied into this repository — attribution and links only (guidelines 10, 14, 16).
  3. **Local verification first (cite-or-abstain).** Verifier kinds: `file_equals`, `file_exists`, `os_release_field`, `binary_present`, `command_ok`. An answer always states whether the fact was *verified on this machine* (`verified` / `doc-sourced` / `unverified-here` when a verifier fails locally — the fact is still cited, but the uncertainty is explicit).
  4. **Online layer is allowlisted and minimal.** Requests only to an explicit URL prefix allowlist (docs.kernel.org, torvalds/linux via api.github.com, man7.org, freedesktop.org, distro wiki domains). Any other URL is refused before a request is made. v1 verifies *existence/attribution upstream*; it does not scrape content into facts (that expansion waits for a real need — guideline 14).
  5. **Surface:** `jarvis explain "<question>"` (grounded, cited answers; refusal when no fact matches — never guesses), `jarvis facts [topic]` (browse the KB), KB version + count in `jarvis status`. Eval: `evals/harness/m4_grounding.py` — gate: **0 unverifiable claims** (answered ⇒ ≥1 source; `verified=true` ⇒ local verifier actually passed; upstream citations checked online in CI).
- **Consequences:** KB growth is manual and reviewed (each fact needs sources; kernel facts need upstream paths that CI re-verifies). Stale facts are detectable: CI fails if a cited kernel-doc path disappears from `torvalds/linux` master. Content-summarization of fetched docs (answering from doc *text*) is deliberately out of scope until M5+.
