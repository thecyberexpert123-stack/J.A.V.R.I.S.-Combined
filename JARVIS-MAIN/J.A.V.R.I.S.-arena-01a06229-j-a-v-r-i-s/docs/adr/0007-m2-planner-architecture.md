# ADR-0007: M2 planner architecture — the LLM proposes, the kernel disposes

- **Status:** Accepted (2026-09-02)
- **Context:** M2 adds LLM planning (owner point 9: API models, local models, and a basic-task engine behind one router). The core risk: an LLM with command-generation ability becomes a hallucination and injection surface directly aimed at the user's machine (guideline 15).
- **Decision:**
  1. **Vocabulary lock.** The planner LLM never emits commands, argv, flags, or paths. Its entire output contract is strict JSON `{"explanation": str, "steps": [intent, ...]}` where each *intent* must pass the same anchored playbook matchers the deterministic engine uses (`planner/llm.py`). Unparseable JSON, out-of-vocabulary steps, injection-shaped text, oversized proposals: refused, never guessed. Schema-validity is measured by `evals/harness/m2_eval.py` (9 cases; 100% required in CI).
  2. **Kernel-only execution.** Materialized plans flow through `Orchestrator.run_plan`, which re-runs every M1 check (builders, static argv analysis, tier gate, journaling, verification, undo composition). Composite undo reverses parts last-first; a part without a reverse path (e.g. `pkg.upgrade`) marks the whole plan's undo honestly unavailable.
  3. **Routing** (ADR-0003 implemented): deterministic engine match → no LLM at all (proven by eval: 0 provider requests); otherwise local Ollama → remote OpenAI-compatible (only if `JARVIS_OPENAI_API_KEY` set and `JARVIS_REMOTE_LLM != 0`) → honest refusal with setup hint. `JARVIS_REMOTE_LLM=0` disables only the *remote fallback*, never local planning.
  4. **Zero-dependency providers.** Both backends speak HTTP via stdlib `urllib` (Ollama `/api/chat` with `format:"json"`, temperature 0; OpenAI-compatible `/chat/completions` with `response_format:"json_object"`). No provider SDKs — supply-chain surface stays empty (guideline 16); keys come from env only and are never logged.
  5. **Chat surface.** `jarvis ask` (one-shot, scriptable) and `jarvis chat` (interactive REPL: `/status /playbooks /tasks /undo /help`) ship as stdlib readline loops. The richer Textual TUI anticipated by ADR-0002 is **deferred** until the interaction model stabilizes — a REPL is testable, dependency-free, and sufficient for the approval workflow (guideline 14). Same for Pydantic: the strict hand-rolled validation pattern proven in M1 (undo-artifact rehydration) covers the narrow fixed schema; the dependency enters only if the schema grows unwieldy.
- **Consequences:** Planner capability growth (free-form commands, multi-machine, non-catalog verbs) is gated behind M3+ sandbox rehearsal, not enabled implicitly. Provider outages surface as honest failures (`planning backend failed`), never as fabricated plans. The eval set must keep 100% schema-validity and refusal coverage to ship.
