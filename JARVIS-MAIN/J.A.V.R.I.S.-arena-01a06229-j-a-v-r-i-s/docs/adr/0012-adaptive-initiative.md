# ADR-0012: Adaptive initiative — suggestions, user context, charters, supervised growth

- **Status:** Accepted (2026-09-02) — owner-directed after v1.1.0 review ("Marvel JARVIS does helpful unrequested things and develops itself over time")
- **Context:** The owner asked how Marvel-style behavior — helpful *unrequested* actions and day-over-day self-development with deep user context — could be designed without betraying this project's kernel philosophy ("never act blindly"; the owner's own guideline: no unsolicited action). Even in-universe, Tony runs JARVIS on standing orders; the self-modifying agent in Marvel is the cautionary tale (Ultron), not JARVIS.
- **Decision — the invariant that makes all of it safe:**
  > **Proactivity proposes; consent executes. Context tunes what is suggested; it never grants authority to act. JARVIS may grow in knowledge, calibration, and skill library (supervised); it may never modify its own code, safety policy, or authority.**
- **Pillars (phased):**
  1. **M8a — Suggestion engine (this milestone).** Read-only `jarvis suggest`: evidence-backed proposals, each citing its evidence (journal timestamps, KB facts with sources) — cite-or-abstain applies to suggestions too. Feedback ledger (`accept`/`reject` + reason, in the context store) seeds M8b; handled suggestions are suppressed from future listings. A suggestion never executes anything: accept prints the exact `jarvis …` command; the engine takes no Runner and cannot run anything (structural, not policy).
  2. **M8b — User context store.** Local `context.db`: explicit preferences, inferred routines (marked inferred, with confidence), feedback ledger, house rules ("never touch Docker"). Inspectable (`jarvis context show`), explainable, deletable (`jarvis context forget`), local-only by default; remote LLM calls get redacted summaries only if the owner opts in.
  3. **M8c — Charters (standing orders).** Scoped, versioned, revocable automation contracts ("refresh+upgrade weekly; never remove packages; tier ≤ T2; pause on failure"), executed via systemd timers; every run is a normal journaled task; `jarvis charter revoke` is instant. Charters are data validated against the tier system; hard ceiling below T3.
  4. **M8d — Supervised growth loop.** JARVIS drafts KB facts (the store refuses uncited ones) and playbook proposals (code + eval cases) as PRs; CI gates; owner merges. It grows knowledge and skills; the kernel and policy are outside its write scope, permanently.
- **Never-bend list (the anti-Ultron clause):** no self-modification of code or policy; no autonomous T3; context never increases action authority; charters rate-limited, revocable, journaled; suggestions cite evidence; everything offline by default.
- **Consequences:** helpfulness scales with trust earned at each rung; every mechanism reuses the existing kernel (tiers, approval, journal, undo, preview/blast radius) instead of adding a parallel one; "deep context" takes weeks of journaled use by design, not a privacy-harvesting shortcut.
