# ADR-0010: GUI control — capability matrix, consent-gated injection, honest per-compositor support

- **Status:** Accepted (2026-09-02)
- **Context:** Owner milestone M5 (GUI control). Linux GUI automation is fragmented by design: Wayland intentionally blocks global synthetic input; each compositor exposes different control surfaces (research basis: Wayland accessibility discussions, per-compositor backend matrices, xdotool-fails-on-Wayland reports, ydotool/uinput semantics). This project's CI can run real X (Xvfb + i3) but has no GNOME/KDE Wayland desktop; the dev sandbox is fully headless.
- **Decision:**
  1. **Detection before action.** `gui/detect.py` builds a `GuiEnvironment` from `WAYLAND_DISPLAY`/`DISPLAY`/`XDG_SESSION_TYPE`, compositor-specific env (`HYPRLAND_INSTANCE_SIGNATURE`, `SWAYSOCK`, `I3SOCK`, `XDG_CURRENT_DESKTOP`), and tool probes. Headless is a first-class, honestly-reported state.
  2. **Capability matrix, not pretending.** A declarative matrix maps (session, desktop, tools) → backend per capability (windows/focus/type/key/screenshot/close). Unavailable = explicit `None` with a reason, never a silent fallback that pretends. Backends v1: X11 (wmctrl/xdotool/scrot), i3/sway IPC (i3-msg/swaymsg JSON tree), Hyprland (hyprctl -j), KDE Wayland (kdotool if present; spectacle), GNOME Wayland (gdbus Shell Screenshot; listing via optional AT-SPI only), generic Wayland input via ydotool (uinput; needs running `ydotoold`).
  3. **AT-SPI is an optional read layer.** Used through `pyatspi` when importable (distro package); absence is reported honestly. It never gates other backends.
  4. **Injection = acting as the user → consent-gated T2 with target disclosure.** `type`/`key`/`focus`/`close`/`screenshot` always show the affected target (focused window name) and go through the same approval + journal path as every other JARVIS action. Injection is CLI-only — it is deliberately NOT reachable from NL playbooks. Text mirrors the file-ops policy (≤500 chars, no control characters); key combos are charset-validated. Window close is T2 (WM delete protocol) with data-loss disclosure; T3 stays reserved for destructive system ops.
  5. **ydotool wizard.** `jarvis gui wizard` runs real checks (binary, ydotoold socket, `/dev/uinput` existence/writability, `input` group membership) and prints exact fix commands for the detected distro (apt/dnf/pacman/apk).
  6. **Vision fallback.** `gui screenshot` captures via the session backend; `gui describe` sends the PNG (base64) to a local Ollama vision model (`/api/chat`, model configurable). Without a reachable vision model the command says so and abstains — no fabricated description.
  7. **Verification model (honest).** Unit tests use scripted runners; the CI `gui-eval` job runs a **real X stack** (Xvfb + i3 + xterm + xdotool + wmctrl + scrot) and a 15-task end-to-end catalog through the actual CLI, gated at ≥98% (⇒ 15/15) plus a headless-honesty subset. Wayland backends are covered by unit fixtures only; **real GNOME/KDE Wayland sessions were not available in this project's infrastructure** and are documented as not verified.
- **Consequences:** GUI support is honest per machine — `jarvis gui status` is the contract. New compositors mean adding a matrix row + backend functions, not new architecture. Input injection can never be triggered by prompt text alone; it requires the explicit CLI with consent.
