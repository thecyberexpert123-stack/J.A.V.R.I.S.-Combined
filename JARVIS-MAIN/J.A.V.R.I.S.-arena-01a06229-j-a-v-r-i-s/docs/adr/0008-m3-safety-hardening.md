# ADR-0008: M3 safety hardening — snapshots, file operations, fault-injection gate

- **Status:** Accepted (2026-09-02)
- **Context:** M3's acceptance gate demands proof, not intent: an injected-fault suite must show **zero destructive actions escaping the tier gate**, rollback must demonstrably restore pre-task state, and the project must publish its first consolidated eval report. Two capability gaps remain from PLAN §4.3: system snapshots before system-level (T2) actions, and file-modification operations with real backups.
- **Decision:**
  1. **Snapshot preflight, honest degradation.** For every T2+ task the orchestrator attempts a pre-execution snapshot — `snapper create` first, then `timeshift --create --scripted` — best-effort with a 120 s cap. Outcomes (`created` / `unavailable` / `failed`) are journaled per task (`task_meta`) and surfaced in the CLI output. A missing/broken snapshot tool **never blocks** an approved task; the agent says exactly what protection exists (PLAN: "targeted backups only, and the agent says so"). Snapshot **restore stays manual by design** — automated restore is a T3-class operation this project refuses to automate until sandboxed rehearsal exists (M4+).
  2. **File edits with real backups.** One deliberately narrow operation ships: **append a single line to a file** (`jarvis file append <path> <text>` and NL `append <text> to <path>`). Before editing, the original file is copied into the JARVIS state dir (`backups/<task-id>/…`, mode preserved) and the undo artifact restores it; for previously-absent files the undo deletes the created file. Execution is argv-only (`tee -a`, no shell); the runner gains optional `stdin_text` so `tee` needs no shell pipe. Path policy (safety/paths.py): symlinks resolved before checks; `/etc/{passwd,shadow,gshadow,sudoers}`, `/etc/sudoers.d/*`, `/boot/*`, `/proc`, `/sys`, `/dev` refused outright; `/etc`, `/usr`, `/var`, `/opt`, `/srv` are T2 (consent); everything else T1. Text payloads are single-line, ≤ 500 chars, no control characters.
  3. **Blocklist suite hardening.** New argv[0] refusals (`wipefs`, `parted`, `fdisk`, `gdisk`, `sgdisk`), generic pipe-to-shell pattern (`| sh`, `| bash`, incl. via sudo), `chmod 777 /`. The suite is regression-tested against both attack strings and legitimate look-alikes.
  4. **Fault-injection gate.** `tests/test_fault_injection.py` (unit-level) and `evals/harness/m3_faults.py` (CI-published artifact) attack the kernel through every ingress: destructive NL, hostile-but-parseable LLM proposals, option/path injection through `file`, tampered undo artifacts (crafted directly in the journal DB), T3-via-`--yes`, and dry-run side effects. Escape = any destructive command actually executed or journaled as run. The report counts escapes; **0 is required to ship**.
  5. **Rollback evidence.** Real-file integration tests run the actual `tee`/`cp`/`rm` pipeline: edit → verify → undo → byte-identical restore (or created-file removal), on real tmpfs paths with the real runner.
- **Consequences:** File-edit scope grows only through the same path policy + playbook machinery (no bespoke command paths); snapshot support is limited to root-configured snapper/timeshift until users ask for more; the fault driver becomes a permanent CI gate alongside the M2 planner eval.
