# ADR-0011: Release engineering — self-contained artifacts, packaged knowledge, owner-gated launch

- **Status:** Accepted (2026-09-02)
- **Context:** Milestone M6 (production hardening & packaging). Acceptance: install tested on clean containers of all Tier-1 distros; full CI matrix green; CHANGELOG complete; zero open P0/P1; v1.0 on branch + PR to `main` opened (never merged by the agent). Audit found one P1: the knowledge base resolved against the *repository root* (`Path(__file__).parents[3]/knowledge`), which silently breaks in any installed wheel — a classic "works in the repo, broken in the package" defect.
- **Decision:**
  1. **The knowledge base ships inside the package.** `knowledge/*.json` moved to `src/jarvis/knowledge/data/` and loaded via `importlib.resources` — schema validation unchanged, curation unchanged, single source of truth (the repo-root copy is gone, not duplicated).
  2. **Artifact set:** pure-Python **wheel + sdist** (zero runtime deps — stdlib only, ADR-0005); **.deb** and **.rpm** that unpack the wheel into `/usr/share/jarvis/lib` with a `/usr/bin/jarvis` shim (no pip-in-postinst, fully self-contained, depends only on `python3 ≥ 3.10`); **AUR PKGBUILD** for Arch users. deb/rpm/PKGBUILD are built and install-tested inside their native distro containers in CI (debian/ubuntu get the deb, fedora the rpm, arch runs `makepkg`), because this sandbox lacks rpmbuild/makepkg.
  3. **Install story (INSTALL.md):** `pipx install jarvis-agent` / `pip install` as the primary path on every distro; native packages for deb/rpm ecosystems; from-source via sdist. One page, per-distro, honest about what is verified where.
  4. **Release pipeline:** tag-triggered `release.yml` (tag `v*` → build all artifacts → smoke-test the wheel in a clean venv → draft GitHub Release with artifacts attached). Evals gain `workflow_dispatch` triggers so fresh verification VMs can be run on demand. The agent never merges and never publishes a *final* release to PyPI — PyPI publishing stays manual by the owner (no trusted-publishing configured; adding one is an owner decision).
  5. **Telemetry: none.** JARVIS contains no telemetry today; per the plan this is an owner decision — nothing is added (guideline 19: no scope creep; guideline 20: human authority).
  6. **Version 1.0.0** marks the milestone-complete v1 surface (CLI+TUI-engine, planner, safety kernel, knowledge, GUI). The Apache-2.0/MIT **LICENSE choice remains owner-reserved** and is called out in the PR — no public redistribution is encouraged until it is decided.
- **Consequences:** wheel/sdist/deb/rpm/PKGBUILD all carry the same versioned, self-contained code; CI proves installation on all five Tier-1 distros from the actual artifacts; releases are reproducible from a tag; the KB can never diverge between repo and package again.
